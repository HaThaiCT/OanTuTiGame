## Decision: corrected installer cleared for bounded isolated commissioning, not runtime-certified

The original154-line draft was unsafe and was not executed. Its findings below are retained as review history; the corrected installer reviewed at snapshot `1AAA` addresses them as described in the final decision section.

1. **Root installation TOCTOU** (`:20-46`): hashes are read from mutable `/tmp` paths, then `install` reopens those paths. An unprivileged actor can substitute bytes between operations. First copy untrusted inputs into a newly created root-owned0700 staging directory under a trusted non-symlink parent; verify the staged bytes against reviewed hashes, then install only those staged bytes. Never execute unverified staged bytes. Validate destination ancestors and reject symlinks before writes; avoid truncating attacker-selected config/unit paths.
2. **Identity/access provisioning is incomplete** (`:49-66,91-116`): UID997/GID984 are assumed, group creation/membership is missing, and root:root0750 `/etc/oantuti` prevents worker/API traversal despite readable group-owned leaf files. Resolve actual intended account IDs and reject collisions; use dedicated shared grant/socket groups and verify the API's current supplementary groups (membership changes do not update an already running API). API owns socket parent0750 and spool0710; worker owns separate attempts0700. API spool and worker materialization roots are distinct. Root owns config ancestors, traversable only to their intended readers.
3. **Artifact roots conflate identities** (`:61-63,107,139`): API `compiledArtifactsDir` is not the worker's artifact output root. Keep an API-owned private durable/staging artifact store and a separate worker-owned0700 output root. Compiled bytes travel via the broker; do not grant the worker write access to API durable artifacts.
4. **No cgroup anchor** (`:133,142`): `worker.rs:588-596,639-649` enables controllers at the configured root and refuses a root containing processes (`control.rs:55-69`). A normal service main process occupies its service cgroup. Start the worker/reaper in an anchor subgroup before execution, leaving delegated root empty; delegate only the new service subtree with cpu/memory/pids available. Attempt/side leaves must expose limit read/write, freezer/kill writes, and event/cpu reads. `Delegate=yes` alone does not satisfy this.
5. **Immutable runtime/rootfs and scoped namespace policy are unprovisioned** (`:72-86,131-135`): validate the actual installed runsc hash/version/flags, immutable rootfs ancestors and complete normalized tree, executable paths and measured toolchain versions. Verify exact runtime-profile JSON SHA separately from rootfs archive/tree identity. Rootfs directory naming and matching JSON hashes are not measurements. Authorize user namespaces only for the immutable installed runsc executable with a narrowly attached AppArmor profile, if required by the host; never change global userns/AppArmor settings, broad sudoers, or use a Docker runtime privilege bypass.
6. **Stop/cleanup and collision handling absent** (`:140-154`): no proof that reaper survives main-worker termination, no bounded drain/cleanup procedure, no stale socket policy, and writes overwrite global paths. Use isolated named service/config/state paths, refuse unrelated existing objects, do not start/restart an existing API or worker accidentally, preserve the sibling reaper, and verify empty workload cgroups/runtime state before considering cleanup successful.

## Corrected implementation and final bounded decision

The corrected installer (`deploy/linux/operator-commission-worker.sh`, snapshot1AAA) is suitable for a local operator's interactive `sudo bash deploy/linux/operator-commission-worker.sh` **installation only**, followed by the isolated acceptance steps above. No privileged action was executed by this reviewer. Root-private snapshots are hashed before installation; immutable rootfs archive/tree is checked before chroot version probes; executable sibling paths/config/profile are pinned; previous destinations and unsafe ancestors are refused; only a new named service and exact installed-runsc AppArmor namespace-exception profile are published. No global sudoers, userns sysctl, Docker privilege bypass, or shared database write is introduced. The script deliberately does not start worker/API or claim readiness.

The service uses dedicated UID997/GID984, DelegateSubgroup=anchor with systemd>=254 check, cpu/memory/pids delegation, no-new-privileges, KillMode=mixed/20s stop grace, Restart=no, and unit-private output tmpfs512MiB (executable for C++ INIT). API durable artifacts remain API-private and separate. The root-owned launch-api wrapper invokes `runuser --user ha-thai --group ha-thai --supp-group arena-supervisor` **before** executing env-cleared Node/user-writable launcher code; that code never executes as root. Process-scoped group984 access avoids giving the worker operator group1000 or persistent account-wide membership changes. API/root config and ancestor traversal permissions satisfy this scoped launch contract. `/run` socket directory is install-session state; after reboot recreate only this reviewed directory with original ownership/mode before startup, or reinstall a separately reviewed tmpfiles rule—no durability claim is made.
