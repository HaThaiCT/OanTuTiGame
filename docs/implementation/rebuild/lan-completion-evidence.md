## Independent security review (LAN delta) and disposition
An independent reviewer attacked the change set and produced nine findings plus design gaps. Fixed in this session, each with a regression that fails without the fix:

1. **Private appeals served anonymously.** `listDisputes` ignored its actor and the route had no session check, so any LAN client could read every team's appeal text and the organizer's reasoning. The service now scopes by actor (organizer: whole ledger; participant: own teams only) and the route requires a session; verified for anonymous, student, uninvolved operator, limited session and organizer.
2. **Retention stripped hold-protected diagnostics.** The diagnostics pass nulled `build_logs`/`execution_logs`/`private_trace` with no holds predicate while the report advertised those rows as held. One shared SQL predicate now feeds both the sweep and the report's held count; the regression fails when the predicate is removed.
3. **Finalize/reopen/DQ/correction bypassed the backup fence.** The class documented "lock/start/finalize refuse on a stale backup" but only lock/start/enrolment asserted it. `finalizeTournament`, `reopenTournament`, `applyCorrection` and `disqualifyTeam` now assert freshness, and the correction service receives the fence from the app wiring.
4. **`REJUDGE` behaved as `VOID`.** A re-play request wrote a fabricated 0-0 no-contest version, which the encounter scorer could read as a decisive void and thereby change who advances. `REJUDGE` now withdraws the current acceptance, records the reason and null replacement version in `result_corrections`, emits `RESULT_REJUDGE_REQUESTED`, and asks the queue for a fresh attempt of the same pinned inputs; no void version is fabricated. Verified: versions unchanged, acceptance withdrawn, game back to `PENDING`, replay callback invoked, second request refused.
5. **Reconciler ignored the deployment generation.** It reclaimed another generation's expired leases and promoted completions without the broker's fence conditions. It now shares the app's generation, filters both queries by it, and requires `j.fencing_token = c.fencing_token`, `j.active_lease_id = c.attempt_id` and `a.fencing_token = c.fencing_token`; verified with a generation-4242 job left untouched by a generation-1 reconciler.
6. **Anonymous team roster read.** `GET /api/v2/teams/:id` returned member user ids and usernames to anyone. It now requires a session and serves the roster only to a full organizer or a member of that team.

7. **Hidden-map content leaked per map, not per version.** The gate read `maps.revealed_at`, stamped once and never cleared, so after any tournament revealed a map the organizer could publish a new version for a *future* tournament and every reader — anonymous, by slug or by explicit version — got that board before its own reveal, and the map pool view served the current descriptor rather than the pinned one. Hidden content is now gated per version: migration `023-map-version-reveal.sql` adds `map_versions.revealed_at` (backfilled for already-revealed maps), the lock stamps exactly the versions the tournament plays — the committed map and every pooled map, read from `tournament_map_commitments` and `tournament_map_pool` — and reads gate on the requested version. Verified end to end: after the first lock the new version is denied to anonymous readers by slug and by version, the revealed version is still served, the public listing shows the revealed version, the future tournament's pool hides what it pinned until it locks, and the organizer still reads the current version. The regression fails against the old map-level gate (verified).

8. **One login-IP bucket behind the planned nginx front.** The API had no `trustProxy`, so behind the reverse proxy every request carried the proxy's address and the 30-attempt/15-minute IP limit became a global lockout; nginx also never forwarded the client address. The API now honours `X-Forwarded-For` only for proxies named in `OANTUTI_TRUSTED_PROXIES` (comma-separated addresses/CIDRs, unset by default so a spoofed header cannot buy a fresh bucket), and `packages/web/nginx.conf` forwards the client address on both the API and WebSocket locations. Verified: with no proxy named, two different forwarded addresses land in one bucket keyed by the socket address; with `127.0.0.1` named, each forwarded client gets its own.

9. **Expired leases were never reclaimed outside the development executor.** The only caller of `JobReconciler.reconcile` was the auto-runner, which is inert unless `OANTUTI_DEV_EXECUTION=1`; in the production shape (dev executor off, native worker on) a worker that died mid-game would leave its job `LEASED` forever — never claimable again, since claims only select `QUEUED`/`RETRY_WAIT`. The API now runs an unref'd reclamation loop of its own whenever the development executor is off (interval `OANTUTI_LEASE_RECLAIM_INTERVAL_MS`, default 5 s), so reclamation is a control-plane duty rather than a side effect of the dev poller. Verified: a job whose worker vanished with an expired lease returns to `RETRY_WAIT` with the attempt marked `EXPIRED`; the regression waits the full timeout and fails when the loop is disabled (verified).

10. **A finalized ledger could be reopened from below.** `invalidateDownstream` set the tournament back to `RUNNING` from `PROVISIONAL` *or* `FINALIZED`, so any future caller reaching the scheduler directly would resurrect a settled competition even though the correction and disqualification paths refuse finalized tournaments themselves. The rebuild now locks the tournament row first and refuses `FINALIZED`/`ARCHIVED` with `TOURNAMENT_REOPEN_REQUIRED` before touching anything, and the state change only accepts `PROVISIONAL`. Verified: only an explicit reopen precedes a rebuild, and the regression fails when the guard is removed.

11. **One team per student per tournament was not enforced.** The product requires it (01 §59/§66) and the workspace merely displayed an error, so an organizer could enroll two teams that share a member, and a captain could add a member who already plays for another team in the same tournament. Enrollment now refuses `TEAM_MEMBER_ALREADY_ENROLLED` (including two teams sharing a member inside one bulk request, reported in the preview), and `addMember` refuses `MEMBER_ALREADY_ENROLLED` for every tournament the team is entered in. Covered by a dedicated suite for the enroll, add-member and intra-request cases.

12. **The legacy compatibility surface still offered self-registration.** LAN_OFFLINE issues every account (01 §4.1) and the new portal uses `/api/v2` only, but `POST /api/auth/register` on the retained v1 surface created an account and a SQLite session for anyone. That endpoint now answers 403 `LEGACY_SELF_REGISTRATION_DISABLED` unless an operator opts in with `OANTUTI_LEGACY_API=1`, and the regression fails when the guard is removed. The rest of the compatibility surface (its own session store and content routes) is still mounted and remains a documented design gap rather than a supported auth plane.

13. **A peer could stop heartbeating to escape its slot budget.** The gateway counted an attempt as occupying a slot only while its lease timestamp had not passed, so a worker could claim, stop heartbeating, wait out the lease and claim again without ever exceeding its own limit. Every `ACTIVE` attempt now counts until the reclaimer expires it — which the API does itself when the development executor is off — so the window is bounded by reclamation rather than by the abandoned lease. Verified: an expired but unreclaimed attempt still refuses the next claim, and the slot frees once reclamation runs; the regression fails against the old query.

Still open, with the reviewer's evidence as the artifact: the remaining design gaps — nothing ties a legal trace to the frozen bots having actually run, and off-host backup evidence is authenticated only structurally (the checkpoint producer, verifier and CLI now exist; the off-host device and custody remain the operator's). Two of the four gaps closed in the software pass below: reauthentication is still enforced per route rather than structurally, and the legacy v1 surface — including its SQLite session store — is no longer mounted at all in a v2 deployment, so it is not a compatibility backdoor to guard.

## Native build path — frozen contract and the frame constraint
The native GAME path ships source to the worker inline in the claim payload, and the gateway frames are capped at 1 MiB (`ipc::MAX_FRAME_BYTES`) while a submission ZIP may legitimately be 2 MiB and a C++ binary can exceed the cap on its own. Inline bytes are therefore a size cliff, not a limitation to work around: `packages/protocol/src/contracts/jobs.ts` now freezes `GrantedArtifact` (per-attempt path + digest + sizeBytes), `BuildAssignment`, `BuildCompletionEvidence` (spec 03 §173: READY with artifact key/digest/size/entrypoint, `SOURCE_REJECTED` with stage and bounded diagnostic, infrastructure faults excluded), `GameBotAssignment` (source grant, optional compiled-artifact grant) and `GameAssignment`. The gateway writes the pinned bytes into an attempt-owned spool and grants exactly that path; the worker verifies digest and size before use and never chooses a path.

Both sides are now implemented on this contract; the server side is verified by its isolated suites and the worker side by the supervisor crate's tests (details below).

**Server side delivered and verified.** At claim time the gateway pins the exact bytes into a fresh attempt spool (`0700` directory, `0600` files, atomic write + fsync, never a worker-supplied path) and the assignment carries path/digest/size grants. BUILD/TEST_BUILD assignments carry the source grant, language, entrypoint, manifest digest, the operator toolchain identity and the limits; the worker streams compiled output back in bounded, strictly ordered chunks (`stageArtifact`, canonical base64, idempotent retries, whole-file hash before it counts), and acceptance requires the toolchain and manifest to equal the assigned ones, the artifact key to be the one this build derives, and the staged bytes to re-hash to the claimed digest — then promotes the artifact durably *before* the single COMPILING/SMOKE_TESTING → READY/REJECTED (or COMPLETED/FAILED) transaction, records `build_error`/`built_at` and an audit event, and treats a replayed completion for a published verdict as a drain rather than a rewrite. `SOURCE_REJECTED` refuses an artifact and requires a non-empty, sanitised, bounded diagnostic. GAME assignments ship per-bot source grants and, for a compile language, the stored artifact grant — refusing a game whose artifact is missing or fails its digest check. `compiled-artifact-store.ts` is content-addressed, atomic and digest-verified on read; the build key is derived from language, source manifest and toolchain, so a worker cannot choose it.

Evidence: `tests/native-build-acceptance.test.ts` (7) and the updated `tests/native-game-acceptance.test.ts` (6) pass, including spool pruning on process restart, spool removal on acceptance and on lease loss, READY keeping the artifact on disk, SOURCE_REJECTED with stage and diagnostic, mismatched digest and mismatched key with no DB mutation, and the CPP game running from the stored artifact.

**Worker side delivered and verified** (`crates/arena-supervisor/src/{worker,materialize,sandbox}.rs`, `bin/arena-worker.rs`): the grant contract is consumed end to end — the granted path is read and verified (size, then SHA-256) before any write, the source is materialized into a fresh attempt, the compile and INIT smoke run inside the sandbox through one shared launch lifecycle (`sandbox.rs` now has a single `runsc` spawn site plus `run_command`, which returns exit status with bounded diagnostics and honours the assignment's own wall limit), the compiled output is hashed and uploaded in ascending chunks through `stageArtifact`, and the verdict distinguishes a command that failed (exit status or wall/output limit under a populated cgroup ⇒ `SOURCE_REJECTED` with the stage) from a launcher, accounting or teardown fault (no evidence, lease left to retry). A CPP game runs the granted compiled artifact and never compiles at match time; a tampered grant or artifact aborts before any write. `cargo test --workspace --offline`: **156 passed / 0 failed** (119 in the supervisor crate, including 16 new build-loop tests), `--all-targets` builds with no warnings.

**Recorded risks rather than hidden ones.** The worker carries a hand-written ZIP/DEFLATE reader because the offline cargo cache contains no vetted archive crate and the environment is offline-only; it re-applies the intake rules (file/size/expanded caps, symlink and traversal bans, case collisions, forbidden extensions) and its input is a digest-verified copy of bytes the control plane already accepted, but the preferred future shape is per-file grants so the worker parses no archive at all. A toolchain's rootfs is pinned as a digest in the operator document and checked by the version probe, not by hashing the rootfs tree at runtime — the release BOM carries that guarantee. As before, no runtime certification is claimed: the worker UID, delegated cgroup, verified runsc and toolchain rootfs do not exist on this host, so every test above scripts the workload or the gateway rather than launching real untrusted code.

**Still to land for this path:** every runtime prerequisite with its canaries (the separate worker UID, cgroup and runsc profile), and the honest limits named above — the gateway proves a trace is well-formed and legal, not that the frozen bots produced it.

## Software completion pass (2026-10-19)

The audited software gaps are closed in code, with the launch and recovery seams that were missing. Verified in this pass:

- **Ordering and recovery.** A completion is now validated, materialised as an immutable fsynced capsule outside the attempt spool, and pinned before any ledger write; `JobBroker.complete` hands the pinned transaction to an independent consumer (`registerCompletionConsumer`) that re-verifies capsule digest, lease/fence/generation provenance and every referenced object, then writes the accepted result/replay/outbox and the terminal job/attempt state in one transaction. The reconciler shares that consumer (`JobReconciler(db, generation, broker)`), so a crash after pinning is finished by a process that never held the assignment; a duplicate `complete` returns the stored canonical receipt and scores nothing twice; and a replayed `prepareCompletion` is answered from the persisted pin even while the backup fence is paused.
- **Deadlock found by running it.** `release()` used a second connection for the snapshot release while the completion transaction held the row, and the transaction was waiting for that call. It now runs on the caller's session; the isolated private-test suite went from a 10 s hook timeout to green.
- **Autonomy.** `TournamentControlPlane` owns registration deadlines, the result outbox, round sealing, job bootstrap and retention without `OANTUTI_DEV_EXECUTION`; the development runner skips those duties when the API owns them. `grace-autoseal.test.ts` proves a grace-0 round seals and a deadline closes with the flag off.
- **Launch.** `OANTUTI_NATIVE_CONFIG` (absolute, operator-owned, not group/world-writable) is validated at startup, rejects coexisting with the development executor, and is wired into the real entrypoint; readiness reports a `workers` check from authenticated claims/heartbeats; a start without game+build worker capability is refused `NATIVE_EXECUTION_NOT_READY`; the silent SQLite fallback is gone; the deployment generation is read from `backup_identity`.
- **Worker runtime.** `arena-reaper` runs beside `arena-worker` (fail-closed if absent), confirms cgroup/runtime cleanup before a slot is reused, and measured CPU/wall/output/protocol violations become attributable forfeits while unmeasured failures stay infrastructure.
- **Evidence of the pass:** server suite **67 files / 431 passed / 1 skipped** on the isolated database at schema 26; Rust workspace **167 passed / 0 failed**, zero warnings; `tsc` clean for every package; `next build` clean, including the self-hosted vendor bracket assets; browser checks on an isolated stack (API 4303 + portal 4304) showed the graphical bracket rendering in a same-origin frame, a guest seeing zero replay links and a role-limited header, the organizer provisioning an account with a one-time credential (audit `LAN_ACCOUNT_PROVISION`), that credential being spent on first login (`PASSWORD_CHANGE_ONLY`; second use rejected 401) and a reauthenticated reset minting a new credential, revoking the account's sessions (0 remaining) and writing `LAN_PASSWORD_RESET`.
- **Observed boundary:** a live delta stream from a *running* game was not observed in the dev demo (matches finish too quickly and no native worker is configured). This remains an explicit UI/runtime smoke gap. Host sandbox certification and off-host backup are operational deployment recommendations, not requirements for the current software delivery.
